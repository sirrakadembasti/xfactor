# Library delivery: static product, docs, security, and UX audit

Scope: read-only inspection of `backend/data/deliveries/kutuphane-takip-sistemi-2.zip` on 2026-09-27. Line references below refer to files **inside that ZIP**. No install, build, server, Docker, or database operation was run for this review. Runtime effects remain to be confirmed in the audit's private scratch environment.

## Findings

1. **High — member deletion irreversibly erases circulation history.** `src/app/api/members/[id]/route.ts:164-177` blocks an active loan, then calls `prisma.loan.deleteMany({ where: { memberId: id } })` before deleting the member. `prisma/schema.prisma:69-71` otherwise declares restrictive loan relations, and `README.md:35` tells operators that related member deletions may be rejected. The UI does disclose deletion of history in its confirmation (`src/app/members/page.tsx:71`), but this still destroys returned-loan records and contradicts the README's retention expectation. **Probe:** in a disposable DB, create a member, loan, and return; DELETE the member; query the loan and dashboard/history counts before and after. Decide whether the product contract permits destruction, then align implementation and docs.

2. **High — write APIs and member personal data have no access control.** `prisma/schema.prisma:10-19` defines `User`, and `src/lib/auth.ts:27-53` defines auth helpers, but none of the 40 shipped `src/**/*.ts(x)` source files calls `requireAuth` or `requireAdmin` outside that helper. For example, `src/app/api/books/route.ts:78-81` begins the create handler with body parsing, and `src/app/api/members/[id]/route.ts:9-59,69-130,140-181` exposes read, update, and delete handlers without a session check. This is a concrete open-access design in the delivered source; severity depends on deployment reachability. **Probe:** from an unauthenticated client against the isolated server, GET `/api/members`, then create/update/delete disposable records; check whether all succeed and whether PII is returned. Require an explicit public/local-only deployment contract or implement authentication and authorization.

3. **Medium — advertised quick-loan navigation does not open the form.** `src/components/Navbar.tsx:84-90,133-140` sends both quick-loan links to `/loans?new=true`. The loans page opens its modal only when `modal=borrow` (`src/app/loans/page.tsx:61-66`); the dashboard correctly uses that query (`src/app/page.tsx:219-220`). **Probe:** visit both links in a browser and check modal visibility. Use one query contract in all links.

4. **Medium — Docker first-run instructions cannot initialize the container database as written.** `README.md:39-46` shows `docker run --rm -p 3000:3000 --env-file .env ...` and says to initialize the schema with `npx prisma db push` before first use. `Dockerfile:8-17` copies the Prisma directory but does not run `db push`; the ZIP has no `prisma/dev.db`. The host's `db push` does not initialize an unmounted container filesystem. The shown `docker run` also does not mount the volume recommended in prose. **Probe:** with a disposable `.env` and container, run the documented commands exactly, request `/api/dashboard/stats`, inspect logs, and repeat with a named volume plus schema initialization inside the container. Update docs/startup behavior to provide an executable first-run and persistence path.

5. **Medium — reported acceptance failure points to files absent from this ZIP.** `DURUM.md:3-5` says `BASARISIZ` because `src/app/api/listings/route.ts` and `src/app/api/listings/[id]/route.ts` call an undefined `prisma.listing`. The ZIP entry list has no `listings` path; its actual API resource paths are books, categories, dashboard, loans, and members, and `prisma/schema.prisma:21-84` defines their corresponding models. This does **not** prove the delivery passes acceptance; it proves the stated reason is stale or refers to a different artifact. **Probe:** compare the ZIP SHA-256 with the verifier input/receipt and rerun the exact static validator on this ZIP; capture paths and hashes in its diagnostic output.

6. **Medium — accessible navigation and forms have missing programmatic targets/names.** `src/app/layout.tsx:32-43` renders a skip link to `#main-content`, but a search of all shipped `src` files found no matching target. `src/app/loans/page.tsx:226-244` uses placeholder-only search and an unlabeled filter select. Its form labels at `:338-397` have neither `htmlFor` nor nested controls. The modal at `:317-327` has no dialog semantics, labelled title, focus handling, or accessible name for the icon-only close button. Similar detached labels appear in `src/app/admin/page.tsx:270-357,385-410`. **Probe:** keyboard-only journey for skip link and loan modal; inspect the accessibility tree for input names; run an axe audit on `/loans` and `/admin`. Add the target, explicit label/control links, dialog semantics, focus restoration/trap, and a close-button label.

7. **Low — date-only due dates are interpreted as instants.** The loan UI sends an HTML `type="date"` value (`src/app/loans/page.tsx:375-385`); `src/app/api/loans/route.ts:124-136` converts it with `new Date(dueDate)`, and overdue filtering compares it with the current instant (`:22,34-37,86-94`). An ISO date-only value is parsed at UTC midnight, so a loan can show overdue during its stated due date. **Probe:** create a loan due today in the isolated DB and request `/api/loans?status=OVERDUE` at midday; compare UI status. Define whether due dates expire at the start or end of the local library day and implement consistently.

## Static review limits

The ZIP source was read directly with Python `zipfile`; the expanded sibling was not modified. The stale `DURUM.md` diagnosis and source-level findings need the private runtime checks above before release conclusions. No XFactor implementation or production data was changed.
